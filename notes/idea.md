# Idea for a Demonstration

I want to make a web page that demonstrates how design choices control inference accuracy for neural networks implemented with analog computer chips. The end goal is a single web page that I will show on a screen. That web page will have ways for me to control different sources of noise, and it will show the consequences of choosing different noise levels in different parts of the system.

A neural network implemented with analog computer chips is, for this purpose, a model of a neural network where each major computational element, such as a convolution, a full matrix multiplication, or a nonlinearity calculation, is computed inexactly. There are several underlying chip technologies that can be used to represent computational elements: charge, voltage, and current. Most literature talks about the "crossbar" being implemented with charge, voltage, or current. We will treat the whole neural net, up to the last step where it outputs a vector of ranked probabilities, as having been implemented with one of these technologies. The model we will use for this demonstration will contribute Gaussian noise of a given amplitude to each computational element. It is that amplitude we set with visual controls on the demonstration page. If we select among charge, voltage, and current implementations, we are selecting how the error from individual operations adds to form a total error for the computational element.

We should also have a choice about what kinds of training weights to use. For instance, a naive training would try to get the best accuracy on the dataset, but using SAM training the results should be more robust. It would be great to select regular or SAM and see how it affects overall accuracy or how it changes the final parameters coming out of the neural network.

If I were really using this for research, it wouldn't be a single web page that doesn't scroll, but here that's what we are limited to. Even with this limitation, we will need a model that is trained two ways (regular and with SAM), and we will need to execute that model with different levels of noise.

I wonder whether, instead of executing the model a thousand times with draws of noise, it would be faster to implement the math just at the level of computational elements? Then we could use our understanding of how charge, voltage, or current add the noise differently from individual calculations, and we could provide just the MOMENT of the noise. Then follow how that moment changes through the calculation and use it to show error on the prediction. It doesn't have to be exact. The audience should understand that choices can matter and that the job of making such a circuit is a codesign job, where hardware and software work together.
